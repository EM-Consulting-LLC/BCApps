# Integration Reference — Гадаад интеграцийн шалгалт

## Суурь зарчим (Base App-ийн sync engine, HTTP кодоос)

- **Идемпотенц бүртгэлээр:** бичлэг бүр sync хийгдмэгц coupling (мэппинг бүртгэл)
  шинэчлэгдэж Commit хийгдэнэ — тасалдсан sync дахин эхлэхэд давхардахгүй.
- **Outbox зарчим:** subscriber зөвхөн queue/log бичлэг үүсгэнэ, илгээлтийг
  Job Queue гүйцэтгэнэ — гадаад системийн доголдол бизнес үйлдлийг блоклохгүй.
- **HTTP:** статус код + reason phrase шалгаж, хүсэлт/хариултыг (нууцгүйгээр)
  логлодог; Authorization зөвхөн SecretStrSubstNo-оор.
- **Delta sync:** Modified On filter — бүх өгөгдлийг дахин зөөдөггүй.

## Дүрмүүд

### BC-INT-001 [CRITICAL] — Идемпотенцгүй импорт/синк
Давтан ажиллахад давхар бичлэг: external id-аар existence шалгалт байхгүй,
checkpoint байхгүй, check-then-insert түгжээгүй. Timeout/algдааны дараах давтан
дуудлагыг заавал бод. **Засвар:** External Id талбар + unique/existence шалгалт +
LockTable; боловсруулсан хэсгээ Commit checkpoint; cursor хадгалалт.

### BC-INT-002 [HIGH] — HTTP алдааны боловсруулалт
Send-ийн boolean, IsSuccessStatusCode шалгаагүй; алдааны body логлоогүй; 4xx/5xx-ийг
амжилт мэт үргэлжлүүлэх.

### BC-INT-003 [MEDIUM] — Retry стратеги
(a) Транзиент алдаанд retry байхгүй чухал илгээлт; (b) идемпотенц баталгаагүй
үйлдлийн автомат retry (давхар гүйлгээ!). Job Queue өөрөө retry хийдгийг тооц —
код давхар retry хэрэггүй байж болно. **Засвар:** идемпотенц түлхүүр + хязгаартай
backoff, эсвэл Job Queue attempts.

### BC-INT-004 [HIGH] — Subscriber-ээс синхрон гадаад дуудлага
OnAfterInsert/Modify/Post subscriber дотор HttpClient — гадаад алдаа бизнес
үйлдлийг унагана, transaction удаан түгжинэ. **Засвар:** outbox: queue табл →
Job Queue → илгээлт + статус.

### BC-INT-005 [MEDIUM] — Partial failure-ийн менежмент
Batch-д нэг бичлэгийн алдаа бүгдийг зогсоох эсвэл бүртгэлгүй алгасагдах.
**Засвар:** бичлэг бүрд Try/Codeunit.Run + алдааны бүртгэл + үргэлжлүүлэлт.

### BC-INT-006 [MEDIUM] — Мэппингийн баталгаа
Гадаад код → мастер мэппинг олдоогүйг чимээгүй алгасах/default руу нуух.
**Засвар:** тодорхой бүртгэж хэрэглэгчид шийдвэрлүүлэх.

## BC-TXN-004-тэй уялдаа

Transaction доторх (uncommitted бичилттэй үеийн) HTTP дуудлага transactions
reference-ийн дагуу давхар шалгагдана.

## Шалгах фокус цэгүүд

- Гадаад системээс ирсэн ID хадгалагдаж байна уу (traceability)?
- Sync хоёр чиглэлтэй бол мөргөлдөөний шийдэл (сүүлийн бичилт дийлэх үү,
  алдаа өгөх үү) тодорхой юу?
- Хугацааны бүс/огнооны формат (UTC vs local) зөв хөрвөж байна уу?
- Webhook хүлээн авагч давхар мэдэгдэлд (at-least-once delivery) бэлэн үү?
